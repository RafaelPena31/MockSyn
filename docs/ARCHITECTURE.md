# Architecture

MockSyn is a Swift Package Manager framework composed of a small runtime module and a macro implementation module. The product is macro-first: users annotate protocols or supported types, and the compiler expands the macro into mocks, stubs, or spies.

MockSyn does not use a build tool plugin, command plugin, source generator, generated source folder, or YAML configuration flow.

## Goals

- Provide MockK/Mockito-style ergonomics in Swift.
- Generate test doubles through Swift macros.
- Keep generated artifacts out of Release builds by default.
- Keep runtime dependencies small and predictable.
- Keep macro expansion deterministic and lightweight.
- Support Swift 5.9 and Swift 6.

## Package Layout

```text
MockSyn/
  Package.swift
  Sources/
    MockSyn/
      Public API
      Runtime
      Matchers
      Captors
      Failure reporting
    MockSynMacros/
      Macro entry points
      Syntax parsing
      Code generation
      Diagnostics
  Tests/
    MockSynTests/
      Runtime tests
      DSL tests
      Failure reporter tests
    MockSynMacroTests/
      Macro expansion tests
      Diagnostic tests
  Examples/
    XCTestExample/
    SwiftTestingExample/
  docs/
```

## Modules

| Module | Responsibility |
| --- | --- |
| `MockSyn` | Public macros, runtime types, DSL, matchers, captors, failure reporting, and test framework adapters. |
| `MockSynMacros` | Macro implementation using SwiftSyntax and SwiftDiagnostics. This module is compile-time only. |
| `MockSynTests` | Tests for runtime behavior and public DSL behavior. |
| `MockSynMacroTests` | Tests for macro expansion and compile-time diagnostics. |

## Macro Expansion Model

The default user code is:

```swift
import MockSyn

@Mocking
protocol UserService {
    func fetchUser(id: String) async throws -> User
}
```

The generated code is conceptually:

```swift
#if MOCKSYN_ENABLE
internal final class UserServiceMock: UserService {
    // Generated mock implementation.
}
#endif
```

The generated source is not stored as a file in the repository. It exists inside the compiler expansion pipeline and the normal build cache, such as DerivedData or `.build`.

## Default Generation Policy

| Area | Policy |
| --- | --- |
| Condition | Generated artifacts are wrapped in `#if MOCKSYN_ENABLE` by default. |
| Access control | Default is `internal`. The user may request a different access level when valid. |
| Release safety | Release builds do not contain generated test doubles unless `MOCKSYN_ENABLE` is active. |
| Generated file | No physical file is generated by default. |
| Runtime dependency | The generated test double references `MockSyn` runtime only inside the `MOCKSYN_ENABLE` region. |

## Data Flow

```text
User protocol/class declaration
  -> Swift macro invocation
  -> Syntax parser extracts members
  -> Validator emits diagnostics for unsupported constructs
  -> Generator emits conditional mock/stub/spy declaration
  -> Runtime stores invocations and stubs during tests
  -> Verify API reports failures through the configured reporter
```

## Runtime Components

| Component | Responsibility |
| --- | --- |
| `Invocation` | Represents one method/property/subscript interaction. |
| `InvocationStore` | Stores invocations in call order. |
| `StubRegistry` | Stores configured return values, thrown errors, and closures. |
| `Matcher` | Compares expected arguments with received arguments. |
| `ArgumentCaptor` | Captures arguments for later assertions. |
| `FailureReporter` | Reports test failures through XCTest, Swift Testing, or a custom reporter. |
| `DefaultValueRegistry` | Provides default values for relaxed mocks. |
| `MockSynLock` | Internal synchronization abstraction. |

## Concurrency Model

The runtime must be safe for async tests. State mutation uses a small synchronization primitive instead of actors, because generated mocks must support synchronous protocol requirements without requiring `await`.

Policy:

- Generated mocks should be safe for concurrent test calls.
- Runtime state mutation must be protected.
- Public APIs should avoid unnecessary `async` unless the mocked member itself is async.
- Swift 6 `Sendable` behavior must be documented per generated type.

## Build Impact Model

Macro annotations affect the target where they are written. MockSyn cannot make that cost zero. The architecture reduces the impact by:

- keeping macro parsing syntax-only;
- avoiding cross-file scanning;
- avoiding build plugins and generated files;
- generating compact code;
- guarding generated declarations with `#if MOCKSYN_ENABLE`;
- keeping SwiftSyntax out of the runtime module.

## Non-Goals

- No full MockK runtime interception model.
- No mocking pure Swift final classes directly.
- No build tool plugin.
- No external source generator.
- No generated source directory as the main workflow.
- No Objective-C runtime dependency in the core package.
