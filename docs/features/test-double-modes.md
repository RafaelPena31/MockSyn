# Test Double Modes

Block 8 makes MockSyn's test-double modes explicit and documented. Generated
mocks, stubs, and spies all carry a `MockSynRuntime` with a `kind` and a `mode`.
The generated initializers allow per-instance mode overrides.

## What It Does

| Feature | Status | Notes |
| --- | --- | --- |
| Strict mock | Supported | Non-void unstubbed calls fail with `MockSynRuntimeError.missingStub`. |
| Relaxed mock | Supported | Supported return types use `MockSynDefaultValueRegistry`. |
| Stub | Supported | Generated by `@Stubbing`; defaults to `.relaxed`, but can be constructed as `.strict`. |
| Spy | Supported | Generated by `@Spying`; records calls and delegates to a wrapped implementation. |
| Partial spy | Supported | Matching stubs override wrapped implementation delegation. |
| Fake helper | Supported | Hand-written fakes can adopt `MockSynFake` to reuse recording and verification helpers. |

## Strict Mock

Strict is the default for `@Mocking` and `@Spying`.

```swift
@Mocking
protocol UserService {
    func name(id: String) -> String
}

#if MOCKSYN_ENABLE
let service = UserServiceMock()

service.name(id: "42") // Fails because no stub was configured.
#endif
```

Use strict mode when a missing stub should fail the test immediately.

## Relaxed Mock

Relaxed mode returns defaults when MockSyn knows how to build the return type.

```swift
let service = UserServiceMock(mode: .relaxed)

service.name(id: "42") // ""
```

Built-in defaults include `String`, `Int`, `Bool`, `Double`, `Float`, `Void`,
and `Optional.none`. Domain defaults can be registered with
`MockSynDefaultValueRegistry`.

## Stub

`@Stubbing` generates a response-oriented double and defaults to `.relaxed`.

```swift
@Stubbing
protocol FeatureFlags {
    func title() -> String
}

#if MOCKSYN_ENABLE
let relaxed = FeatureFlagsStub()
relaxed.title() // ""

let strict = FeatureFlagsStub(mode: .strict)
strict.given.title().willReturn("Preview")
strict.title() // "Preview"
#endif
```

Use strict stubs when every non-void response should be explicitly configured.

## Spy And Partial Spy

Spies require a wrapped implementation. When no matching stub exists, the spy
delegates to the wrapped value. When a matching stub exists, the stub wins.

```swift
let spy = UserServiceSpy(wrapping: realService)

spy.name(id: "42") // delegates

spy.given.name(id: .value("offline")).willReturn("Cached")
spy.name(id: "offline") // "Cached"
```

This is the partial spy behavior: real implementation by default, targeted
overrides only where the test needs them.

## Fake Helper

Fakes are hand-written domain objects. They are useful when behavior is more
important than configuring individual return values.

```swift
final class FakeUserService: UserService, MockSynFake {
    let __mockSyn = MockSynRuntime(kind: .fake, mode: .relaxed)

    func name(id: String) -> String {
        mockSynRecord(member: "name(id:)", arguments: [id])
        return "fake-\(id)"
    }

    func verifyName(id matcher: MockSynMatcher<String>) -> MockSynVerification {
        mockSynVerification(member: "name(id:)", matchers: [matcher.erase()])
    }
}

let fake = FakeUserService()

_ = fake.name(id: "42")

try fake.verifyName(id: .value("42")).once()
try fake.mockSynConfirmVerified()
```

`MockSynFake` does not generate code. It only shares runtime helpers for manual
fakes that want the same recording and verification behavior as generated
doubles.

## Current Limits

- Generated fakes are not part of the macro surface. Use hand-written fakes plus
  `MockSynFake`.
- Static member stubbing and verification share the generated type-level runtime
  state and use the macro's configured default mode.
- Testing-framework adapters are not implemented yet; verification currently
  throws `MockSynVerificationError`.
